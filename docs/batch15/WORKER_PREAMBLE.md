# Common instructions for every Batch 15 worker

Run the assigned research session using Astra (`gpt-6-astra`), with xhigh reasoning where available. Record the model that actually ran each phase. Banked Claude code and mathematics remain shared inputs with original attribution; this batch needs no live Claude session. Work independently from the frozen base. Read this file, `ACCEPTED_STATE.md`, your brief, the named input files and applicable repository instructions before committing the preregistration.

**Base and ownership.** The dispatch message supplies the expected full commit, tree and annotated tag object. Resolve `git log -1 --format=%H batch15-base` and `git log -1 --format=%T batch15-base`; compare exactly. Start your assigned `b15-NN-*` branch at that commit in an isolated checkout. Never start from moving main or another worker's output. If the project is absent, obtain the repository and local launch bundle using `BOOTSTRAP.md`; a missing checkout is a setup task, not a research conclusion. If an input truly cannot be recovered, report it and pursue the brief's independent fallback.

Commit `results/PREREG_b15_NN.md` first. Specify inputs and hashes, exact mathematical question, algorithm, positive/negative controls, resource envelope and decision thresholds. Then implement and perform the bounded run. Report every outcome, including a resource stop, in `docs/b15_NN_report.md`. Use `analysis/b15_NN_*`, `results/b15_NN/`, `docs/b15_NN_proved.md`, and logs prefixed `b15_NN_`. The proof fragment is a per-slot record with claim, hypotheses, evidence status, verifier and dependencies. Proposed exclusions go to `results/b15_NN/proposed_exclusions.json`; the integrator alone updates the canonical theorem index and exclusion ledger. This supersedes the old contract's shared-file section and prevents concurrent section-letter collisions.

Do not edit protected papers, `PROJECT_NOTES.md`, `docs/boundary_deficit.html`, `docs/PROVED.md` or `results/integrate/inherited_exclusions.json`. Propose corrections in your own files. Reusable changes to a shared implementation need a focused replay and a clearly described patch. Preserve other sessions' work and original artifacts. Include actual model attribution in commit trailers. Deliver a bundle; do not push.

**Mathematical decisions.** Record n, degree, ambient variable count, partition, point family and representation convention. Distinguish ambient multiplicity a, ideal multiplicity i, coordinate multiplicity m, pullback dimension h, orbit and closure. Apply the current scoped ledger plus the accepted-state overlay before evaluation. Compute U_pad=min(a,h_pad,a-L_pad,other valid upper bounds). A valid determinant rank floor r_det>=U_pad excludes positive D. A positive needs a global determinant upper bound U_det and a padded rank floor r_pad>U_det; equivalently q_det+r_pad>a with i_det>=q_det globally. Stable deficient sample ranks are candidates, not ideal lower bounds. Use full target completeness and exact arithmetic for the interpolation exception.

Define true independently padded points. Through degree8, banked cubic closure and transfer give m_pad=m_red under their stated hypotheses; direct padded witnesses remain useful for a short certificate. Do not assume this in higher degree. Preserve coefficient factorials, u, label indexing, source orientation, primes, polynomial definitions and any change of basis. A modular source must have a justified rational lifting or integral construction. Count before allocating a carrier; signed Burnside sizes cannot be replaced by a stabilizer quotient. Cost construction, reduction and evaluation separately.

**Resources and controls.** All twelve reasoning sessions may start together. At most two heavy numerical jobs run on the shared host at once; the integrator allocates the initial leases in each dispatch. Without a lease, perform proof, code, counts and small controls first, then request a lease in the task. Default: one process/BLAS thread per numerical run, 15-minute pilot, 90-minute production attempt, aggregate cap1.5GiB. Measure before extending a budget and record every change. A session is not limited to one attempt if a failed attempt leads to a justified new method; avoid repeated unchanged runs.

Use `analysis/b15_bound.py --slot NN --name b15_NN_RUN --seconds 900 --memory-mb 1536 SCRIPT [ARGS]` on Windows after its small resource control. This inherits the accepted CI73 Job Object mechanism. Use an equivalent tested aggregate limit on other systems, not a POSIX command pasted into PowerShell. The Python process records its own PID and resource log; archive those files. Before ending a current process, verify its identity and start time, because archived PIDs can be reused. Temporary cleanup may remove only a checked, uniquely created child directory; preserve caller outputs. Begin from available RAM and avoid oversubscription even below nominal caps.

Use UTF-8. Confirm NumPy, optional python-flint and any compiled backend actually required by your algorithm. Install dependencies into the worker's own environment if needed. Accepted CI73 also has a C# backend and the packet supplies a NumPy modular adapter; neither is a universal replacement for every flint API. Missing flint alone is not a reason to discard a valid alternative. Dependency availability and small controls are worker preflight gates, not blanket assumptions in this board.

A source/evaluator must pass a separate known liveness control. Allow the research cell's determinant rank to be zero; do not make the desired answer a control requirement. Use altered source, point, sign or normalization data to show relevant checks detect defects. Do not describe stored-matrix elimination as a fresh geometric replay. Statuses are EXACT, REPLAYED_RANK_FLOOR, RECORDED, CANDIDATE, or RESOURCE_STOP, with inherited premises named separately. Fields for bounds use _lb/_ub; estimates name the method; uniqueness flags carry modulus, integer bound and signed margin.

**Delivery.** Use the house wording guide for new prose, retaining historical documents unchanged. Every new tracked artifact must be below5,000,000 bytes; split larger data with a replayable join. Retain complete native inputs or a compact source construction and explicit points, not only saved values. Save a concise replay command, return code, wall time, aggregate peak memory and input hashes. State which facts were freshly checked and which were inherited.

After all work is committed, run `python tools/delivery/check_batch15.py --branch YOUR_BRANCH --base BASE_COMMIT --slot NN`. Then run `python tools/delivery/package_batch15.py --branch YOUR_BRANCH --slot NN --model gpt-6-astra --output delivery/b15_NN_final`. Use a fresh output directory. The helper creates the one-ref delta bundle, checksum files and canonical manifest after the last commit, then runs the post-bundle check. `bundle_prerequisites` is a one-element JSON array containing only the full base hash. Large local bundles get ordered parts below5MB. No hash self-reference: the manifest is external to the bundled commit. A packaging PASS does not verify mathematical claims.

Return the report, delivery location, exact head/tree, checked findings and the next sufficient missing witness. Report ambiguities or incorrect premises in the brief; correcting an assignment is useful work. Do not wait for another Batch15 session unless the integrator offers a verified optional relay. Independent fallbacks are mandatory.
