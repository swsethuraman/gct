## The lemma you will implement (state it, prove it in two lines, then validate it)

Let `lam` have blocks of equal parts with sizes `k_1..k_t` and values
`m_1..m_t`, so `Stab_W(lam) = S_{k_1} x ... x S_{k_t}` acts on the
`lam`-weight space of `C[W]_delta` by permuting variable indices within
blocks.  **Every highest-weight vector `v` of weight `lam` satisfies
`P_w v = chi_lam(w) v` with `chi_lam(w) = prod_B sgn(w_B)^{m_B}`.**  Proof:
`P_w v` has weight `w(lam) = lam` and lies in the irreducible `V_lam`
generated by `v`, whose `lam`-weight space is one-dimensional; the scalar is
intrinsic to `V_lam` (any two copies are `G`-isomorphic, and `P_w` is in
`G`), and on the leading-minor model of the highest-weight line a
transposition inside a block of value `m` acts by `(-1)^m`.  At rectangular
`lam` this is exactly s33's `sign^delta` lemma.

Consequence: the HWV space of weight `lam` lies inside the
`chi_lam`-isotypic component of the weight space, of dimension
`n_chi ~ N_S / |Stab_W(lam)|`.  Implement the pipeline on the isotypic basis
(twisted orbit sums of weight-`lam` monomials; orbits whose twisted sum
vanishes drop out), apply the raising operators there, take the kernel, and
evaluate at points exactly as the house pipeline does.  Resident memory is
then governed by `n_chi`, not `N_S`: use s33's blocked-echelon model
(`~8·n_chi^2` bytes resident) and its certified compressed-kernel route on
top (`docs/e4_hunt.md` §4), re-validated here on general weights before use.

**Validation battery — mandatory, and it must contain tests the lemma would
FAIL if wrong** (s30's lesson: quote the discriminating count, not the pass

## Point construction — this is where a subtle error would live

- det points: `det_4(sum_{i<=r} s_i A_i)`, random `4x4` `A_i`, as always.
- **pad points at `r >= 6` must be true padded-permanent restrictions**:
  `F = l(s) · per_3(A(s))` with `A` a `3x3` matrix of random linear forms in
  `s_1..s_r`.  At `r = 5` this coincides with `l·(random cubic)` because
  `per_3`-pencils are dense in quinary cubics; **at `r = 6` it does not**
  (`dim D_6^{per_3} = 50 < 56`), and using `l·(random cubic)` there would
  over-estimate `mult_pad` and could manufacture a false `D > 0`.  Use the
  true construction at every `r`, and say so in the ledger header.
